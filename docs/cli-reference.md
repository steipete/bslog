# CLI reference

This page collects bslog's command and option reference. Run `bslog <command> --help` for the help generated by the installed version.

## Commands

| Command                            | Purpose                                          |
| ---------------------------------- | ------------------------------------------------ |
| `bslog tail [source]`              | Fetch recent logs and optionally keep polling    |
| `bslog errors [source]`            | Fetch entries classified as errors               |
| `bslog warnings [source]`          | Fetch entries classified as warnings             |
| `bslog search <pattern> [source]`  | Search raw log text                              |
| `bslog trace <requestId> [source]` | Filter on `requestId`, optionally across sources |
| `bslog query <query>`              | Parse a GraphQL-inspired query                   |
| `bslog sql <sql>`                  | Execute raw ClickHouse SQL                       |
| `bslog sources list`               | List available Better Stack sources              |
| `bslog sources get <name>`         | Show one source                                  |
| `bslog config set <key> <value>`   | Save a configuration value                       |
| `bslog config show`                | Show effective configuration                     |
| `bslog config source <name>`       | Set the default source                           |

## Shared log options

`tail`, `errors`, `warnings`, `search`, and `trace` share these options:

| Option                 | Meaning                                                   |
| ---------------------- | --------------------------------------------------------- |
| `-n, --limit <number>` | Number of rows, from 1 through 10000; defaults to 100     |
| `--since <time>`       | Inclusive lower time bound                                |
| `--until <time>`       | Inclusive upper time bound                                |
| `--format <type>`      | `pretty`, `json`, `table`, or `csv`                       |
| `--fields <names>`     | Comma-separated selected fields                           |
| `--sources <names>`    | Comma-separated sources to merge                          |
| `--hot-only`           | Query hot storage only; excludes archived logs            |
| `--where <filter...>`  | One or more `field=value` JSON filters                    |
| `--jq <filter>`        | Run JSON output through `jq` if it is available in `PATH` |
| `-v, --verbose`        | Print generated SQL and debugging details                 |

Normal log commands query both Better Stack hot and archived storage, so they include archived matches. `--limit` still caps the rows returned. Use `--hot-only` for low-latency reads where archived results are not needed. `tail --follow` is always hot-only because it polls for new entries.

`tail` additionally accepts `--level`, `--subsystem`, `--follow`, and `--interval`. `search` also accepts `--level`. The GraphQL-inspired `query` command also accepts `--hot-only`.

Values passed through `--where` recognize booleans, numbers, `null`, quoted strings, and JSON object or array values. Repeat the option to combine equality predicates:

```sh
bslog search "timeout" my-app-production --where service=api --where attempt=3 --since 1h
```

Use `--fields` to keep machine-readable output small:

```sh
bslog errors my-app-production --fields dt,message,requestId --format json --limit 20
```

## Query syntax

The query form is `{ logs(arguments) { fields } }`:

```sh
bslog query "{ logs(level: 'error', since: '1h', limit: 50) { dt, message } }" --source my-app-production
```

Supported arguments are:

| Argument         | Value                                 |
| ---------------- | ------------------------------------- |
| `limit`          | Integer from 1 through 10000          |
| `level`          | Log level string                      |
| `subsystem`      | Subsystem string                      |
| `since`, `until` | Relative time, date, or timestamp     |
| `between`        | Two-element `[since, until]` array    |
| `search`         | Raw-text search string                |
| `where`          | Object of structured equality filters |
| `source`         | Better Stack source name              |

Select `*` for the raw payload or list fields separated by commas. Field names support dot paths, bracket indices, and quoted keys, including `metadata.proxy[0].status` and `metadata["complex key"].value`.

## Raw SQL

`bslog sql <sql>` sends ClickHouse SQL directly to the Query API. If the statement has no output format, bslog appends `FORMAT JSONEachRow`. Raw SQL does not use the Telemetry API to resolve a source, but current client initialization still expects `BETTERSTACK_API_TOKEN` in addition to Query API credentials.

## Time values

`--since` and `--until` accept:

| Form                     | Examples                |
| ------------------------ | ----------------------- |
| Relative                 | `30m`, `1h`, `2d`, `1w` |
| ISO 8601                 | `2026-08-02T12:00:00Z`  |
| Date                     | `2026-08-02`            |
| Runtime-parsed timestamp | `2026-08-02 12:00:00`   |

Relative values are calculated from the current time. Absolute values are parsed by the JavaScript `Date` runtime and converted to UTC for ClickHouse.

## Output

| Format   | Behavior                              |
| -------- | ------------------------------------- |
| `pretty` | Colorized, human-readable entries     |
| `json`   | JSON array for scripts and pipes      |
| `table`  | Terminal table                        |
| `csv`    | CSV with discovered fields as columns |

When `--jq` is present, bslog selects JSON automatically. If `jq` is unavailable or exits unsuccessfully, bslog reports the error and prints the unfiltered JSON.

Multiple-source commands query each source, merge rows in descending `dt` order, add a `source` field, and apply the requested overall limit. Follow mode polls each source independently.

## Configuration

Configuration is stored at `~/.bslog/config.json`.

| Key            | Meaning                     | Default                                        |
| -------------- | --------------------------- | ---------------------------------------------- |
| `source`       | Default Better Stack source | None                                           |
| `limit`        | Default query limit         | `100`                                          |
| `format`       | Saved output format         | `json`                                         |
| `logLevel`     | Default level filter        | `all`                                          |
| `queryBaseUrl` | Query API endpoint          | `https://eu-nbg-2-connect.betterstackdata.com` |

Valid saved formats are `json`, `table`, `csv`, and `pretty`. Commands currently use their own output defaults unless `--format` is passed. Valid log levels are `all`, `debug`, `info`, `warning`, `error`, `fatal`, and `trace`; `warn` is normalized to `warning`.

`BSLOG_QUERY_HOST` overrides the saved `queryBaseUrl`. Credentials are read from environment variables and are not written to this file. Query history is retained in the same file, up to 100 entries.

## Built-in source aliases

The current CLI expands these aliases before source lookup:

| Alias                | Source name           |
| -------------------- | --------------------- |
| `dev`, `development` | `sweetistics-dev`     |
| `prod`, `production` | `sweetistics`         |
| `staging`            | `sweetistics-staging` |
| `test`               | `sweetistics-test`    |

These aliases are project-specific. Use the exact source names from `bslog sources list` for other Better Stack accounts.

## Troubleshooting

### Missing Telemetry API token

`BETTERSTACK_API_TOKEN environment variable is not set` means source discovery cannot authenticate. Export the token described in [Authentication](authentication.md).

### HTTP 403 from a query

Query API credentials are region-specific. Check that `BSLOG_QUERY_HOST` or `queryBaseUrl` matches the cluster shown beside the credentials in Better Stack.

### Source not found

Run `bslog sources list` and use the exact returned name. A saved default source and built-in aliases are resolved through the same lookup.

### Query timeout

Reduce `--limit`, narrow the `--since` and `--until` window, and confirm the Query API endpoint is reachable. Network requests time out instead of waiting indefinitely.
